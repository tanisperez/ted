Move through a diff with F7, a minimap and syntax colors, drag and drop, a tab menu, and updates from the app with an install script and APT and DNF repositories.

## Highlights

- **Move between the changes of a diff**: Previous and Next in the diff header, or `Shift+F7` and `F7`, with a counter of the current change. Past the last change, `F7` again opens the next changed file; `F4` opens the file at the change. In a narrow window the header shows the buttons as icons and cuts the folder first.
- **Minimap in the diff**: the right edge of a diff shows where the changes are in the whole file, in their colors, with the visible part as a box. Click or drag on it to go there.
- **Faster git diffs with syntax colors**: opening the diff of a changed file runs about three git commands instead of two plus one or two per change block, most noticeable inside WSL. The code is colored as in the editor, and lines with tabs keep the marks of the changed words.
- **Drag and drop**: files and folders dropped from the file manager open, and in the explorer a file or a folder dragged onto a folder moves there, asking before replacing one of the same name. Open tabs follow the files they show.
- **Tab menu**: right click a tab for Close, Close others, Close to the right, Close to the left, Close saved and Close all, plus the path items for a file, the same menu as Postino. Closing several tabs with unsaved changes asks once for all of them, with Save all, Don't save and Cancel.
- **Context menus from the keyboard**: `Shift+F10`, or the menu key on Linux and Windows, opens the menu of the active tab under it. The arrow keys, Enter and Esc work in it.
- **Resize the Markdown split view**: drag the line between the editor and the preview to share the width, and double click it for half and half.
- **Fold all and Unfold all** in the editor's right-click menu: Fold all leaves only the first level of the file on screen. The menu ends with **Wrap lines**, checked while long lines wrap, as `Alt+Z`.
- **Updates from the app**: ted looks for a new version once, a few seconds after it starts, downloads it and shows **Update ready, restart** in the status bar; nothing is installed until you click it. On macOS, with the Windows installer and on Linux with the install script in your home folder. Other copies say when a new version exists. The check can be turned off in Settings, About.
- **Install script for Linux**: `curl -fsSL https://ted.tanis.codes/install.sh | bash` installs ted for your user on any distribution, and running it again updates it.
- **APT and DNF repositories**: Debian, Ubuntu, Fedora and openSUSE can install the `ted-editor` package from ted's own repositories and get updates with the rest of the system.
- **Download page**: the buttons download the files of the latest release directly, with a package picker for Linux.
- **A larger app icon**: the icon fills its whole square, as Postino's, so ted no longer looks smaller next to other apps in the dock or the taskbar.
- **XML declaration colored**: `<?xml version="1.0"?>`, DOCTYPE, processing instructions and CDATA are highlighted, with a grammar of their own for XML.
- **Pull shows its count**: in the branch menu, Pull shows how many commits the branch is behind, as Push shows how many it is ahead.
- **Right-click menus** in every text field (the find bar, Go to line, the global search and the language menu) have ted's style on every platform and add Undo and Redo.
- **Menus open on click**: the file switcher, the branch menu and every other drop-down menu open when the mouse button is released, like a click on a button, instead of as soon as it is pressed.
- **Updated libraries**: the UI toolkit moves to gpui-kit 0.10.0, and the other dependencies to their latest compatible versions.

## Fixes

- **`ted` in a Windows terminal works like any other tool**: `ted --help` prints in cmd and PowerShell and the shell waits for it, its output can be piped, and opening a file from a terminal gives the prompt back at once.
- **The window no longer opens tiny on Windows**: closing ted while it was minimized saved a negative size, and the next start opened the smallest window.
- **A larger minimum window size**: the window can no longer be made smaller than 1024 × 640, below which the title bar lost the settings button.
- **Commit buttons of the same width**: in the Git panel, Commit and Commit and push… share the row in halves when they fit and stack at full width when the panel is narrow.
