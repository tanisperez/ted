title: Installation description: How to install ted on Windows, macOS and Linux, put it on the PATH, and build it from source. ---

Installation

Every release on GitHub has packages for Windows x86_64, macOS on Apple silicon and Linux x86_64. The download page links to them.

Windows

Run ted-X.Y.Z-windows-x86_64-setup.exe. It installs ted for your user only, under %LOCALAPPDATA%\Programs\ted, and needs no administrator rights. The installer offers three options:

  • Add ted to the PATH, checked: run ted file.txt or ted . from any new terminal. Uninstalling removes it again.
  • Add "Open with ted" to the Explorer menu, checked: on every file, on folders and on the background of an open folder.
  • Create a desktop shortcut, unchecked.

ted also shows in the Open with list of the usual text files (.txt, .md, .log, .json and others) without becoming their default app; see ted as the default app. Scripts that Windows runs on a double click (.bat, .cmd, .ps1, .py, .pyw, .js) are left out of that list, so they keep running; open them with "Open with ted" in the Explorer menu or from ted itself. To use ted without installing anything, unzip ted-X.Y.Z-windows-x86_64-portable.zip and run ted.exe.

macOS

Open ted-X.Y.Z-macos-arm64.dmg and drag ted to Applications. ted then shows in Finder's Open With menu of text files and folders. A Mac app cannot put itself on the PATH; to run ted from a terminal, link it once:

```shell $ sudo ln -sf /Applications/ted.app/Contents/MacOS/ted /usr/local/bin/ted ```

Linux

The packages install ted in /usr/bin, with its desktop entry and icons, so ted shows in your applications menu and in the Open With menu of text files and folders. The package is named ted-editor, because another app already uses ted in the AUR; the command is still ted. It replaces the ted package of versions up to 0.4.1.

Install script

On any distribution, one command installs the latest release for your user, with no sudo:

```shell $ curl -fsSL https://ted.tanis.codes/install.sh | bash ```

The script downloads the tarball of the latest release from GitHub, checks it against the release's SHA256SUMS and installs it under ~/.local: the program in ~/.local/bin/ted, and the menu entry and the icons under ~/.local/share. It also writes the list of the files it installed to ~/.local/share/ted/installed-files, so updating and uninstalling touch exactly those. If ~/.local/bin is not on your PATH, it says so; the menu entry works either way.

Run the same command again to update to the latest release, or let ted update itself. It never installs a pre-release unless you ask for it with --version.

To pass options, put them after bash -s --:

```shell $ curl -fsSL https://ted.tanis.codes/install.sh | bash -s -- --uninstall ```
OptionWhat it does
--version X.Y.ZInstalls that release instead of the latest one.
--prefix DIRInstalls under DIR instead of ~/.local. A system folder such as /usr/local needs sudo bash. Pass the same --prefix to update or uninstall.
--uninstallRemoves the files the script installed. Your settings and logs stay, and the script prints where they are.
--purgeWith --uninstall, also deletes your settings and logs (see Files and folders). Your files are never touched.
--tarball FILEInstalls from a release tarball already on disk instead of downloading one, and does not check it against the release's checksums. The in-app updater uses it after verifying the file. It does not go with --version or --uninstall.
-h, --helpShows the options.

The script runs only on Linux x86_64 and needs curl, tar and sha256sum. Run it as your user: as root it asks for a --prefix, since installing into root's home would leave ted where nobody finds it. If ted is already installed in /usr/bin by a package manager, the script stops and asks you to remove that copy first, so you never have two copies that update differently. You can read the script before running it at ted.tanis.codes/install.sh.

Debian and Ubuntu (apt)

Add the signing key and the repository once, then install. Your usual apt upgrade keeps ted up to date.

```shell $ sudo curl -fsSLo /etc/apt/keyrings/ted.asc https://ted.tanis.codes/ted.asc $ echo "deb [signed-by=/etc/apt/keyrings/ted.asc] https://ted.tanis.codes/apt stable main" \ | sudo tee /etc/apt/sources.list.d/ted.list $ sudo apt update && sudo apt install ted-editor ```

Fedora and openSUSE (dnf, zypper)

Add the repository once, then install. The signing key is imported on the first install.

```shell # Fedora $ sudo curl -fsSLo /etc/yum.repos.d/ted.repo https://ted.tanis.codes/rpm/ted.repo $ sudo dnf install ted-editor # openSUSE $ sudo zypper addrepo https://ted.tanis.codes/rpm/ted.repo $ sudo zypper install ted-editor ```

Arch Linux (pacman)

Download ted-editor-…-1-x86_64.pkg.tar.zst from the latest release and install it with pacman:

```shell $ sudo pacman -U ted-editor-0.7.0-1-x86_64.pkg.tar.zst ```

There is no pacman repository nor AUR package yet, so pacman -Syu does not update ted: install the package of the next release the same way. The install script is the alternative that updates with one command.

AppImage

The AppImage, ted-X.Y.Z-x86_64.AppImage, runs on any distribution once it is executable (chmod +x), and installs nothing. It does not update itself: download the new AppImage and replace the old one.

Tarball

The tarball, ted-X.Y.Z-linux-x86_64.tar.gz, holds bin/ted and the desktop files in a /usr layout, to copy wherever you like. The install script does this for you.

ted as the default app

Installing ted never changes which app opens your files. To make ted the default for a type, choose it yourself, and the files of that type then show ted's document icon, with the type written on it (MD, TXT, LOG, JSON...):

  • Windows: right click a file, Open with, Choose another app, pick ted and Always. Windows remembers it. This needs the installer: the portable zip registers nothing.
  • macOS: select a file, File, Get Info, pick ted under Open with and press Change All.
  • Linux: pick ted in your file manager's Open With dialog (with Remember in Dolphin), or run xdg-mime default codes.tanis.ted.desktop text/markdown. Linux file managers draw the icon of a file type from the icon theme, whatever app opens it, so the icon only changes if you turn on Show ted's icon on the files it opens by default in Settings. ted then gives its icon, for your user only, to the types whose default app is ted, and follows your choices while it runs. Your file manager may need a reload (F5) to show it.

First launch

ted is not code signed yet. On macOS, if the system says it cannot verify the developer, choose Open Anyway in System Settings, Privacy and Security. On Windows, if SmartScreen shows Windows protected your PC, choose More info and then Run anyway.

Every release lists the SHA-256 checksum of each package in SHA256SUMS.

The in-app updater checks once, a few seconds after launch, and never polls in the background. When a new version exists it downloads it, verifies its checksum and shows Update ready, restart in the status bar. Nothing is installed until you click it. You can turn the automatic check off in Settings, About.

Building from source

ted builds with the stable Rust toolchain. On Linux it needs the development packages of Wayland, X11, xkbcommon, fontconfig and Vulkan; the README lists them.

```shell $ git clone https://github.com/tanisperez/ted $ cd ted $ make release $ ./target/release/ted ```
