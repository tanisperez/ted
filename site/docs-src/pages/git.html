title: Git description: The Git panel of ted: see what changed in a folder, stage, discard and commit. ---

Git

When the open folder is inside a git repository, the Git panel lists what changed and lets you stage, discard and commit without leaving the editor.

What it needs

ted runs the git installed on your computer, version 2.30 or later; it does not bundle its own. It finds it on the PATH, or you can pick the executable in Settings, Git. Without git, or with a folder that is not a repository, ted works as before and the panel says why it is empty. A folder that is not a repository can be turned into one with Initialize repository.

The Git panel

The Git toggle of the status bar, or Ctrl Shift G, shows the Git panel in place of the explorer; the Files toggle brings the explorer back. The toggle shows how many files changed. The panel lists them in two groups:

  • Changes: tracked files that were modified (M), added (A), deleted (D, struck through), renamed (R) or that have a conflict (!).
  • Unversioned: files git does not track yet (U).

Files are grouped by folder; the list button in the header shows them as a flat list with their folder next to the name. Click a group or a folder to fold it, and a file to open it.

Staging

The checkbox of a file, a folder or a group stages or unstages everything under it, as git add and git restore --staged would. It mirrors the git index, so it agrees with the terminal: a file with staged and unstaged changes shows a dash. When files outside the open folder are staged, a notice over the list says so, because they would go into the next commit, and offers to unstage them.

Discarding changes

The undo arrow that appears when you point at a row discards its changes: a modified file goes back to its last committed version, and an unversioned file is deleted. The arrow in the header discards every change. ted asks first, unless Confirm before discarding changes is off in Settings. Discarded changes cannot be recovered.

Committing

The box at the bottom of the panel commits what is staged. Write the message and press Commit, or Ctrl Enter in the message (Cmd Enter on macOS). The line over the buttons says what the commit will include: the number of files and the lines added and removed. The message stays disabled while nothing is staged.

  • Amend replaces the last commit instead of adding one. Ticking it with an empty message brings back the last commit's message, so you can also only reword it.
  • Commit and push… commits, then lists the commits about to leave and asks before pushing them. The first push of a new branch sets its upstream on the remote.
  • The Ctrl+Enter in the message setting makes Ctrl Enter commit and push instead.

ted runs git with your own configuration: your name and email, your hooks, and your credential helper or SSH agent for the remote. While a commit or a push runs, the status bar says so. When one fails, a notification explains why in plain words, and Show git output shows what git printed.

Branches

The status bar shows the current branch (or the short id of the commit, when HEAD is detached), with an up arrow and the number of commits to push and a down arrow and the number to pull. Click it to open the branch menu:

  • The search box filters the branches and the actions as you type.
  • New branch, Pull, Push (with the number of commits to push) and Fetch at the top. Pull merges or rebases as your git configuration says (pull.rebase).
  • The branches in groups: Recent (the current one and the last ones you checked out), Local and one group per remote. Each one shows its last commit, how long ago it was made, and how far it is ahead or behind its upstream.
  • Click a branch, or press Enter on it, to check it out. A remote branch checks out its local branch, creating it when needed.
  • The arrow at the end of a branch opens its submenu: check out, a new branch from it, rename and delete. A branch with commits that are not merged anywhere asks again before it is deleted.
  • Type a name that does not exist and press Ctrl Enter to create that branch from the current one and check it out.

When you check out another branch with uncommitted changes, ted asks what to do with them:

  • Stash and check out keeps them in a stash named after the branch they belong to (ted-auto:main). When you come back to that branch, ted restores them and says so.
  • Bring changes takes them to the other branch, which only works when they do not conflict with it.

After a checkout or a pull, the explorer follows the files on disk, and an open file that changed is reloaded, asking first when it has unsaved changes. A rejected push offers Pull and push.

Refreshing

The status is read when the folder opens and when the panel is shown; the circular arrow in the header reads it again. A failed git command shows git's own message in a notification.
